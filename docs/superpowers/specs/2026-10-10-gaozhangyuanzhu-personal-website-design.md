# 高瞻远瞩个人网站设计规范

日期：2026-10-10  
状态：待用户确认

## 1. 项目目标

构建一个公开可访问、有个人风格、可长期维护的个人网站。网站主人为「高瞻远瞩」，当前主要定位是学生，网站用于展示自我、记录生活、表达观点、发布博客和提供资源下载。

核心关键词：

- 二次元
- 赛车
- 摄影
- 骑行
- 音乐
- Vibe

成功标准：

- 访客能在几秒内理解主人的身份、兴趣和个性。
- 网站包含简历、博客、观点、生活记录、资源下载五个核心内容区。
- 主人可以通过添加或修改 Markdown 文件更新内容。
- 网站在桌面端和移动端均清晰可读。
- 网站可部署到 GitHub Pages 或 Vercel，并通过公网访问。

## 2. 设计原则

- 以个人气质为核心，避免模板感过重。
- 首页强调身份、关键词、精选内容和个性签名。
- 内容分层清晰：正式简历与轻松生活记录分开。
- 网站保持静态优先，降低部署和维护成本。
- 初期结构简单，后续可以扩展相册、音乐记录、评论和自定义域名。

## 3. 技术方案

### 技术栈

- 框架：Astro
- 语言：TypeScript
- 样式：Tailwind CSS
- 内容：Markdown
- 部署目标：GitHub Pages 或 Vercel

选择 Astro 的原因：

- 静态网站生成能力强，默认输出轻量页面。
- Markdown / Content Collections 支持成熟，适合博客和记录。
- 页面默认少 JavaScript，首屏速度快。
- 后续如需复杂交互，也可以逐步引入组件或迁移页面。

## 4. 页面与功能

### 4.1 首页

目标：让访客快速认识「高瞻远瞩」。

内容：

- 顶部导航：首页、关于、博客、观点、生活、资源。
- 主视觉：ID「高瞻远瞩」、身份「学生」、个性签名、头像或标志性视觉。
- 关键词标签：二次元、赛车、摄影、骑行、音乐、Vibe。
- 精选内容：2 至 4 篇博客或观点。
- 最近生活记录：2 至 3 条时间线卡片。
- 底部：社交链接、版权信息和返回顶部入口。

视觉方向：

- 使用有呼吸感的留白和清晰排版。
- 主色固定采用红色、白色和黑色，营造速度感、个人态度和赛车氛围。
- 卡片带有轻微圆角、阴影或渐变边框。
- 支持深色 / 浅色模式。
- 页面动效保持克制，例如淡入、hover 缩放或渐变流动，不使用过度动画。

### 4.2 关于 / 简历页

目标：展示个人背景、能力、经历和联系方式。

模块：

- 个人简介：学生身份、兴趣、当前方向。
- 兴趣关键词：二次元、赛车、摄影、骑行、音乐、Vibe。
- 教育经历：学校、时间段、专业或学习方向。
- 项目与作品：学习项目、摄影集、骑行记录、个人网站等。
- 技能标签：根据主人后续提供的信息填充。
- 联系方式：邮箱、社交平台、作品平台、GitHub 等。
- 下载入口：提供可下载的简历 PDF，初始阶段可使用占位文件。

### 4.3 博客

目标：发布较长文章，用于思考、项目记录、兴趣总结和生活写作。

功能：

- 博客列表按时间倒序展示。
- 每篇文章包含标题、日期、标签、摘要、正文。
- 支持封面图。
- 支持分类标签筛选。
- 文章详情页展示完整 Markdown 内容。
- 底部推荐相关文章。

Markdown frontmatter：

```yaml
---
title: 文章标题
description: 文章摘要
date: 2026-10-10
tags:
  - 二次元
  - 摄影
cover: /images/blog/example-cover.jpg
draft: false
---
```

### 4.4 观点

目标：发布较短的判断、态度和碎片思考。

功能：

- 观点列表按时间倒序展示。
- 单条观点支持标题、日期、标签和短正文。
- 观点页比博客更轻，排版更直接。
- 初期不做独立评论系统。

Markdown frontmatter：

```yaml
---
title: 观点标题
date: 2026-10-10
tags:
  - Vibe
  - 学生
draft: false
---
```

### 4.5 生活记录

目标：以时间线方式展示日常生活、照片、爱好片段。

内容形式：

- 文字记录。
- 单张或多张照片。
- 日期与地点。
- 相关兴趣标签，例如骑行、摄影、赛车、音乐、二次元。

列表形式：

- 按时间倒序展示。
- 每条记录使用卡片或时间线样式。
- 点击后可进入详情页查看完整记录和图片。

Markdown frontmatter：

```yaml
---
title: 一次城市骑行
date: 2026-10-10
location: 上海
tags:
  - 骑行
  - 摄影
photos:
  - /images/life/ride-1.jpg
summary: 沿江骑了四十公里，顺手拍了一些傍晚光线。
draft: false
---
```

### 4.6 资源下载

目标：提供主人愿意公开分享的文件和链接。

模块：

- 资源列表：名称、说明、标签、日期。
- 文件下载按钮。
- 外部资源跳转按钮。
- 无可用资源时显示简洁空状态。

初期资源：

- 简历 PDF 占位文件。
- 示例资源说明文件。
- 摄影或壁纸示例资源目录占位。

## 5. 内容模型

### 博客集合

字段：

- `title`：必填，文章标题。
- `description`：必填，列表和 SEO 使用的摘要。
- `date`：必填，发布日期。
- `tags`：可选，标签数组。
- `cover`：可选，封面图路径。
- `draft`：可选，默认 `false`。

### 观点集合

字段：

- `title`：必填，观点标题。
- `date`：必填，发布日期。
- `tags`：可选，标签数组。
- `draft`：可选，默认 `false`。

### 生活记录集合

字段：

- `title`：必填，记录标题。
- `date`：必填，记录日期。
- `summary`：必填，首页和列表使用的摘要。
- `location`：可选，地点。
- `tags`：可选，标签数组。
- `photos`：可选，图片路径数组。
- `draft`：可选，默认 `false`。

### 资源数据

初期使用本地数据文件维护资源列表。后续如果资源数量增加，可以迁移为 JSON 或 Markdown 集合。

字段：

- `title`
- `description`
- `category`
- `tags`
- `date`
- `type`：`file` 或 `link`
- `href`

## 6. 视觉系统

### 色彩

网站主色调固定为红色、白色和黑色，整体形成强烈的个人风格。

- 主红色：`#E10600`，用于强调按钮、链接、标题装饰、标签高亮和关键交互状态。
- 深黑色：`#0A0A0A`，用于默认深色背景、主要文本、页脚和部分卡片。
- 纯白色：`#FFFFFF`，用于深色背景上的主文本、浅色模式背景和核心内容区域。
- 辅助灰：`#6B7280` 与 `#E5E7EB`，仅用于次级说明、分隔线、边框和弱化信息。
- 深色模式：黑色背景 + 白色正文 + 红色强调。
- 浅色模式：白色背景 + 黑色正文 + 红色强调。
- 不引入紫色、青色或其他主要装饰色；渐变和阴影只能基于黑、白、红构建。

### 字体

- 中文正文使用系统默认中文字体栈，避免加载过大的网页字体。
- 英文与数字使用清晰的无衬线字体。
- 标题可以加粗并略微收紧字距，增强个人品牌感。

### 组件风格

- 卡片：圆角、轻边框、hover 时轻微位移或阴影变化。
- 标签：小圆角胶囊。
- 按钮：简洁填充或描边样式。
- 图片：统一圆角和比例约束。
- 导航：移动端折叠为简洁菜单。

## 7. 响应式与可访问性

- 页面使用移动端优先布局。
- 手机端导航、列表、图片和下载按钮必须可点击。
- 图片提供替代文本。
- 标题层级遵循 `h1` 到 `h3` 的语义顺序。
- 文本对比度符合基本可访问性要求。
- 键盘可以访问导航和核心链接。
- 页面包含基本 SEO 信息：标题、描述、Open Graph 图片。

## 8. 错误处理

- Markdown frontmatter 字段不符合 Content Collections schema 时，构建失败并提示具体文件。
- 文章设置 `draft: true` 时，生产构建不输出详情页，开发模式可选择显示。
- 下载文件缺失时，资源卡片不在生产构建中展示，避免出现死链。
- 外部链接统一使用 `target="_blank"` 和 `rel="noopener noreferrer"`。
- 访问不存在的页面时展示 404 页，并提供返回首页入口。

## 10. 初始内容

网站初期需要占位内容，避免页面空白：

- 至少 3 篇博客示例。
- 至少 3 条观点示例。
- 至少 3 条生活记录示例。
- 至少 2 个资源下载示例。
- 一份关于我页面框架，具体教育经历、联系方式和技能由主人后续替换。

占位内容会明确标注为示例，方便后续删除。

## 11. 部署方案

### 首选：Vercel

- 将项目推送到 GitHub 仓库。
- 在 Vercel 中导入仓库。
- 使用默认 Astro 构建配置。
- 部署后获得公开访问地址。
- 后续可绑定自定义域名。

### 备选：GitHub Pages

- 使用 GitHub Actions 构建 Astro 项目。
- 将静态产物发布到 `gh-pages` 分支或 GitHub Pages 工作流目标。
- 通过 `https://<username>.github.io/<repo>/` 访问。
- 需要在 Astro 配置中设置正确的 `site` 和 `base`。
